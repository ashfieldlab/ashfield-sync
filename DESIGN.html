Ashfield Sync: 설계 결정

ADR-0015 (2026-06-12 결정) 의 grilling 정리 · 원문: ashfield-drive/docs/adr/0015-desktop-client.md
로그인: Keycloak → Ashfield 계정 서버로 교체 (2026-10) · 계약: ashfield-account/docs/adr/0001-account-server-contract.md
배경: 웹 브라우저 단독 파일 접근의 다운로드–편집–업로드 사이클 불편 (HWP 라운드트립 · 큰 파일 · 오프라인)
상태 (2026-06-13): Phase 1·2·3 완료 (Authenticode 서명만 보류). 양방향 sync(크기 무관) + 트레이 상주 + 온보딩 + 자동 업데이트 + SSE + OpenAPI 자동생성, Windows 실기기 검증.

결정 12개

완료

1Tauri (JS UI + Rust)

Electron 대신 Tauri. UI 는 React, 시스템 통합은 Rust (windows-rs). binary ~10–20MB (Electron 100MB+ 대비).

대안: Electron(무거움) / 순수 Rust GUI(생산성↓) / .NET(스택 이질)

완료

2Windows-only

macOS / Linux 명시적 미지원. 타깃 사용자 (한국 기업/공공) 거의 전부 Windows. 잘못된 가정으로 판명 시 별도 ADR.

완료

3Cloud Files API: Files On-Demand

Windows native VFS. placeholder (수 KB) → 열면 hydrate (1MB 스트리밍 CfExecute). FUSE/WebDAV mount 의 quirk 회피.

구현: CfRegisterSyncRoot(E1) · CfCreatePlaceholders(E2) · FETCH_DATA 콜백 hydrate(E3) · polling 연동(E4) · 자동 bootstrap(E5). 428MB 파일도 로컬처럼 열림 검증.

완료

4OAuth 2.1 + PKCE: Ashfield 계정 서버 SSO

App Token paste 패턴 회피. 시스템 브라우저 → Ashfield 계정 서버(/api/auth/oauth2/authorize, 디스커버리로 확인) → loopback callback (http://127.0.0.1:1421/oauth/callback, 등록값과 정확히 일치) → token 교환. public client ashfield-sync (secret 없음, PKCE S256 · state · nonce · iss 확인). refresh_token 은 Windows Credential Manager.

resource = Drive public URL. authorize·token·refresh 모두 resource=<VITE_DRIVE_RESOURCE>: 그래야 access token 이 JWT(aud ∋ Drive URL)로 나와 Drive 백엔드가 JWKS 로 검증. scope openid profile email offline_access. 계약: ashfield-account/docs/adr/0001-account-server-contract.md (Keycloak 대체).

App Password 는 headless / 표준 프로토콜용 탈출구: GUI 클라이언트는 OAuth 정공.

완료

5access_token 자동 refresh

401 → single-flight refresh → 재시도 1회. refresh 실패 (revoked / SSO 종료) 시 "세션 만료" 안내 + 로그인 화면 복귀.

refresh_token 회전 · 재사용 감지. 갱신마다 새 refresh_token 을 keychain 에 저장. 옛 값을 다시 쓰면 계정 서버가 토큰 패밀리 전체를 폐기하므로, UI(401) · SSE 재연결 · VFS hydrate 스레드의 갱신을 Rust oauth.rs 한 곳(락 + 공용 access token 캐시)으로 직렬화. SSE 는 401 이면 새 토큰으로 즉시 재연결. 로그아웃 = revocation_endpoint 로 refresh_token 폐기 + keychain 삭제.

완료

6양방향 sync + 충돌 사본

ETag (If-Match) optimistic locking. 로컬 변경(notify watcher)을 직렬 큐로 backend 반영: 신규/수정/삭제/이름변경.

구현: F0 overwrite API(write-to-new-key+swap) · F1 watcher(self-write 로 hydrate 자기변경 무시) · F2 업로드 · F3 충돌 사본 foo (충돌본 2026-06-13 PC명).docx · A 대용량 multipart 업로드. 작은 파일·큰 파일·신규·수정 전부 양방향 대칭.

backend 완료

7Delta polling 1분

GET /api/v1/nodes/changes?since=: audit_logs 기반. 권한 회수도 access_revoked 로 내려와 placeholder + cache 즉시 삭제. SSE 는 Phase 3 이후.

완료

8Sync 범위

Personal + Shared (회사×{내 파일,회사 공유}). Trash 제외 (Windows 휴지통과 혼동 방지). ExternalLink 는 외부 사용자용이라 무관. FileShare 받은 것은 후속.

수정됨

9Multi-company: 회사별 root 폴더

활성 회사 전환 개념 없음: 동시 sync. ~\Ashfield\{회사}\... 웹 sidebar 와 1:1.

2026-06-12 수정: 온보딩에서 sync 회사 선택(opt-in) → opt-out 모델로 변경. 기본 = 전체 회사 sync (placeholder 라 디스크 비용 ~0). 제외는 설정 화면 toggle. 신규 회사 배정 시 자동 등장. 온보딩 = 로그인 + 폴더 위치 확인만.
Phase 4 검토

10Multi-device 자동

backend 는 device 추적 안 함. 회사 PC + 집 PC 동시 OK: 충돌은 ETag + 충돌 사본으로. device registration 은 SaaS 단계 검토.

완료

11별도 repo ashfield-sync

release cycle 분리 (월 단위 vs 매 commit). API contract 는 OpenAPI auto-generate (Phase 2–3): backend 변경이 컴파일 에러로 잡히게.

완료

12표시 이름 "Ashfield Sync"

브랜드 + root 폴더 ~\Ashfield\ 일관. 앱 표시 이름은 Ashfield Sync.

사용자 흐름 (현재 동작)

1. .msi 설치 → 첫 실행 2. 시스템 브라우저 → Ashfield 계정으로 로그인 ← 계정 서버 SSO 3. 로컬 폴더 확인 (default ~\Ashfield\) ← opt-out, 자동 bootstrap 4. 첫 sync: placeholder 생성 ← 동작 5. 탐색기에서 파일 보임 → 클릭 → 자동 hydrate ← 동작 (vault 는 복호화 hydrate) 6. 편집 → 저장 → 자동 upload → 1분 내 반영 ← 동작 (vault 는 암호화 upload)

Phase 로드맵

Phase 1: POC ✅OAuth ✓ · 자동 refresh ✓ · tree ✓ · 설정 저장 ✓ · delta polling ✓ · VFS placeholder + hydrate ✓
Phase 2: 양방향 ✅로컬 변경 감지 ✓ · 양방향 sync ✓ · 충돌 사본 ✓ · 대용량 multipart 업로드 ✓  (남음: OpenAPI contract)
Phase 3: 외부 배포 ✅트레이 상주 ✓ · 온보딩 마법사 ✓ · 자동 업데이트(minisign) ✓ · SSE nudge ✓ · OpenAPI 타입 자동생성 ✓ · 커스텀 타이틀바 ✓  (보류: Authenticode 서명)

E2E 보안 폴더 (Vault, ADR-0016)

특정 폴더를 봉투 암호화: 개발자·관리자조차 못 봄. 키 체인: 비밀번호 ─argon2id→ KEK ─AES→ 개인키 ─RSA→ vault_key ─AES→ {파일명,DEK} ─AES→ 파일. 서버는 암호 연산 0, 불투명 blob·ciphertext 이름만 보관. 싱크는 web 과 동일 봉투를 재사용.

완료

V5a: 이름 복호화 · 구조 유지

잠금해제 시 vault 파일/폴더명을 복호화해 표시(잠김=내용 숨김, 루트만). prune 은 startup·잠금토글 시 1회만: 매 sync 마다 돌면 막 만든 미업로드 로컬파일이 날아가는 레이스가 생겨 금지.

완료

V5b: hydrate 복호화

FETCH_DATA(OS 스레드)는 JS 를 await 못 함 → JS 가 DEK 를 사전 적재(vfs_set_deks, node_id→raw 키). whole-file AES-GCM 이라 전체를 받아 한 번에 복호화. placeholder 크기 = size_bytes − 28(iv12+tag16) 로 평문과 일치시켜 잘림 방지.

완료

V5c: 암호화 업로드 (편집 지원)

싱크의 목적은 편한 편집: vault 도 써야 함. vfs_encrypt_to_temp 가 평문을 [iv][ct][tag] temp 로 암호화 → 기존 업로드 머신(single/multipart) 재사용. create/modify(+wrapped_dek) · rename(암호화 이름) · delete. 평문은 이름·내용 모두 서버로 안 나감.

남음

V6: 공유 · 복구 · 표시

공유(타인 공개키로 vault_key wrap) · 복구코드 생성/표시 · plain_size 표시(현재 vault 파일 크기가 암호문 +28B 로 보임).

재검토 / 알려진 한계

항목현재재검토 방향
임시파일 무시 휴리스틱
watcher::is_ignored		 파일명 패턴만으로 판단: ~$·.~lock.·.tmp·.swp·.crdownload·.part·.DS_Store·Thumbs.db. 내용·상태가 아니라 이름 추측. 정확하지 않음: 재설계 필요. ① 목록에 없는 임시패턴 놓침(~문서.docx·.bak·편집기별 랜덤 임시명·atomic-save temp). ② 사용자가 진짜 메모.tmp 로 지으면 동기화 누락. 후보: 편집기 atomic-save 실관찰 후 패턴 보강 / debounce 안정화 후 최종본만 / 무시목록 사용자 설정화.
vault 파일 크기 상한 200MB 초과 거부(상태줄 안내). whole-file AES-GCM = 평문+암호문 통째 메모리(~2배), 매 저장 전체 재업로드. 거부된 큰 파일이 로컬에만 남아 다음 startup prune 에 삭제될 수 있음(놀람). prune 제외 또는 vault 밖 이동 안내 보완. 대용량 필요 시 청크/프레임 AEAD(스트리밍·랜덤액세스, 포맷 변경)로 전환.
평문 hydrate 잔재 잠금해제 후 연 파일은 평문이 디스크에 남음. 로그아웃 시 DEK 만 폐기. prune-on-logout 미구현: 현재는 다음 로그인 startup prune 이 백스톱. 즉시 청소하려면 로그아웃 시 vault prune 호출.
vault 동시 편집 충돌 412 시 평문 충돌사본을 못 만들어 서버 버전 우선(로컬 변경 버려질 수 있음). 비-vault 의 충돌사본 대칭을 vault 에도 주려면 사본을 암호화해 새 노드로: 추후.

메인 화면 · 운영 메모

메인 창 구성 (개편)

암호문 이름+etag 를 그대로 뿌리던 원시 노드 트리 덤프 제거. 싱크 클라이언트다운 구성으로 교체:

• 동기화 상태 카드: ✅정상/⚠️오류 + 마지막 확인 메시지
• 📂 동기화 폴더 열기: opener 플러그인으로 탐색기 오픈 (capability: opener:allow-open-path + scope **)

dev vs build: 빈 화면 함정

target\debug\*.exe 는 UI 를 dev 서버(localhost)에서 로드. 단독 실행(부팅·트레이·더블클릭)하면 dev 서버가 없어 ERR_CONNECTION_REFUSED 빈 화면.

개발=npm run tauri dev (Vite+exe 동반). 단독 실행 앱=npm run tauri build (프론트 번들). autostart 는 release 빌드만 등록: debug 는 disable() 로 잘못 등록된 부팅 시작도 정리.
